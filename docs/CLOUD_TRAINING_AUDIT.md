# Cloud training audit and replacement workflow

27 October 2026. Code/provenance review, not a new accuracy measurement.

The user's Colab experiment is the 71-feature CERT AE. Its historical results
are separate from the existing 12-feature cloud checkpoint. Existing artifact
metadata are not a complete record of the exact code/data used for training.
Both existing checkpoints remain untouched and the live instance stays unscored.

Public-data follow-up: see PUBLIC_CLOUD_DATA_AUDIT.md. The Ariel release's benign
base has short per-principal history and unresolved reuse terms; it has not been
admitted to this training path. CLUE-LDS is a preliminary behavioural benchmark
candidate requiring a source-specific adapter/feature review, not fabricated AWS
lab provenance. Neither dataset changes the audited-lab input gate below.

## Legacy findings

* build_cloud_dataset.py labels Level5/Level6 attacker and all remaining identities
  normal. These identity heuristics are not verified event-level ground truth.
  The flaws.cloud publisher describes the collection as largely attacks and notes
  that the flaws role was exposed through the challenge. Treating that role and
  other identities as clean normal training data is not justified by their names.
* train_cloud_ae.py sorts by date but splits rows at an 80% index. Multiple user
  rows from the same day can fall on both sides of the cutoff.
* The validation set selects the best epoch and also sets score bounds. There is
  no independent normal calibration period in that path.
* The generated legacy notebook reports a same-dataset metric including training
  rows. Its separate cross-validation section does not make that first metric
  held-out, nor establish performance on connected cloud accounts.
* The legacy notebook embeds a second feature implementation. Future changes can
  diverge from the serving extractor. The new notebook imports pinned repo code.
* Feature documentation says scaling to [0,1], but the actual pipeline uses
  StandardScaler. This audit preserves the actual frozen feature/scoring contract.
* Latest-day live scoring may use an incomplete day; full-day offline evaluation
  does not validate those intermediate scores. AWS-only data do not validate
  Cloudflare/GitHub/Entra detection or person-level identity correlation.

Source: [flaws.cloud dataset publisher](https://summitroute.com/blog/2020/10/09/public_dataset_of_cloudtrail_logs_from_flaws_cloud/).
These findings establish reasons to rebuild provenance, not the exact contents
or quality of a checkpoint whose full training manifest is absent.

## Local export

```powershell
python scripts/export_cloud_baseline.py --manifest data/live/experiments/RUN/manifest.json --out data/live/training/VERSION/dataset.json
```

Repeat --manifest for non-overlapping successful baseline runs. The exporter
rechecks native CloudTrail evidence and rejects partial audits, failed runs,
duplicate events and mixed labs. It selects SDK actions from accepted runs only,
never the entire connected database. It aggregates UTC user-days with strictly
prior-day history through the frozen shared function, preserves original dates
and pseudonymises identity keys. Raw logs, IPs, resource names and credentials
are not exported. Hashes/counts record inclusions and exclusions.

This is a controlled AWS lab dataset, not independently verified normal employee
behaviour. It omits unaudited role/session/setup events. A deployment baseline
must additionally review the difference between these action-only snapshots and
all actor activity visible to serving. Export hashes and local manifests support
traceability; they are not cryptographic attestation of benign activity.

Re-export after UTC days close: same-day rows are marked incomplete. The current
single-day run cannot satisfy training requirements. More events within the same
day do not create additional identity-day samples or history.

## Colab training

Open cloud_ae_verified_training.ipynb, generated by
scripts/build_verified_cloud_notebook.py --revision FULL_REVIEWED_COMMIT.
It checks out an immutable commit, installs pinned CPU training dependencies,
accepts only the feature JSON after checking its locally reported SHA256, and
runs a readiness check before opt-in training. No cloud credentials are needed.

Training requires at least five closed UTC training days and 30 training rows,
then separate later validation/calibration periods with six rows and six
identities each. Six identities are also required in training. These are modest
operational minimums, not statistical proof or a guarantee of generalisation.
Use varied normal routines across actual days; do not repeat identical rows or
change timestamps to pass the checks. Freeze before collecting the held-out
transition. Keep a genuinely later normal control period too.

StandardScaler fits training only; validation chooses weights; independent
normal calibration sets p5 and twice-p95 reconstruction-error bounds, preserving
the existing serving score equation. The score is not a probability, and existing
risk tiers remain provisional. No attack data select the model or calibration.

Output is a new candidate directory with cloud_ae_v1.pt, cloud_scaler_v1.pkl and
frozen_model_manifest.json. It records data/code/artifact hashes, UTC cutoffs,
partition counts, seed, Python/dependency versions and evaluation_status=
not_evaluated. Seeded CPU tests reproduce tensor values in the tested environment;
bitwise portability across library versions/platforms is not promised.

Downloading the bundle is not installation. A later explicit installation must
verify hashes and fixed-input inference against Colab, preserve the original
models, place the reviewed bundle inside ml/models and refresh/restart scoring.
The manifest uses bundle-relative filenames; the actor gate expects installed
files beneath ml/models. No model was trained on live data or activated by this
implementation task. CERT results and live-cloud results must remain separate.
