# Spec: W0.1-test-hardening — close the two known test-suite gaps

**Branch:** `w0-1-test-hardening` · **Executor:** executor (sonnet) · **Written:** 2026-07-04

## Goal
The suite passes deterministically regardless of local `data/events.db` contents, and the
paginated /users envelope metadata is actually asserted. Closes the PR#1 review finding and
LESSONS.md rule 10.

## Non-goals
- No production code changes UNLESS the envelope's `total` proves genuinely wrong under a
  risk filter (then STOP and report — that's a product bug the planner must see first).
- No changes to scoring, features, or thresholds. No new test frameworks/plugins.

## Files in scope
- backend/tests/ (test_api.py, conftest.py, or a new test file)

## Approach (planner-decided)
1. **Fix the state-dependent test** (`TestGetStats::test_get_stats_total_matches_n_users`,
   fails 28 vs 25 when local events.db has seeded cloud users). Root cause: /stats totals
   include event-store (cloud) users on top of the N_USERS CERT parquet users. Fix at test
   level, NOT by purging anyone's DB: isolate the event store in tests. Read conftest.py
   first — if the app/client fixture can point the event store at a fresh temp SQLite file
   (tmp_path) via the store's config/env, do that for the whole suite (deterministic
   baseline). If isolation is impossible without production-code changes, weaken the
   assertion honestly instead: `total >= N_USERS` plus an exact-match on the CERT-user
   count if the response exposes it — with a comment citing LESSONS.md rule 10.
2. **Assert the envelope metadata** in TestGetUsers: `total` == full user count and is
   consistent across pages (same value regardless of limit/offset); `limit`/`offset` echo
   the query params; `len(users) <= limit`; `total` consistency when `?risk=` filters
   (filtered total must equal the filtered count, not the global count).
3. Run the full suite twice to prove determinism: once as-is, once after the isolation
   fixture is active. Both green.
